# The native iOS project, in writing

`ios/` is generated by `npx cap add ios` and is **gitignored**, so every setting
that lives inside it has to be written down somewhere that isn't. This is that
place. Recreate the project on any Mac with `npm run build && npx cap add ios`,
then apply everything below once.

`TESTFLIGHT.md` covers signing, archiving and upload; this file is only the
native configuration a fresh clone would otherwise lose.

## `ios/App/App/Info.plist`

| Key | Value | Why |
| --- | --- | --- |
| `ITSAppUsesNonExemptEncryption` | `NO` | Standard HTTPS/OS crypto only. Skips the export-compliance prompt on every upload. |
| `NSCameraUsageDescription` | *MyTailLog uses the camera to photograph your logbook pages.* | `@capacitor/camera` throws at launch without it. |
| `NSPhotoLibraryAddUsageDescription` | *MyTailLog can save captured logbook pages to your photos.* | Required even for camera-only capture. |
| `NSPhotoLibraryUsageDescription` | *MyTailLog accesses your photos to add existing logbook scans.* | Adding scans you already have. |
| `UIBackgroundModes` | **absent** | We do NOT want background fetch. Reminders arrive as an APNs alert; nothing runs while the app is closed. Adding this key invites an App Review question with no good answer. |

After editing, **Product → Clean Build Folder**. App Store Connect validates the
*uploaded* plist, not the one on the device you've been testing with.

There is no usage string for notifications: iOS asks for that permission through
the system prompt with no app-supplied text.

## Entitlements: two files, one per configuration

`cap sync` creates `App/App.entitlements` with `aps-environment` = `development`.
That value is correct for a cable-attached run from Xcode and **wrong for
anything distributed** — iOS refuses to register a TestFlight build whose
entitlement says `development`, and the plugin's `registrationError` is the only
place it says so. Symptom: the permission prompt appears, the owner accepts, and
`device_token` stays empty forever.

So there are two files, selected by build configuration:

| Configuration | `CODE_SIGN_ENTITLEMENTS` | `aps-environment` |
| --- | --- | --- |
| Debug | `App/App.entitlements` | `development` |
| Release | `App/AppRelease.entitlements` | `production` |

Recreate `App/AppRelease.entitlements` as a copy of `App.entitlements` with
`production`, then set the Release configuration's `CODE_SIGN_ENTITLEMENTS` to
point at it (Build Settings → Code Signing Entitlements, Release row only).
`cap sync` does not touch the Release file.

`APNS_ENV` in Secret Manager must match what the build actually carries:
`production` for TestFlight and the App Store. Check the shipped value with
`codesign -d --entitlements :- <App.app>` on the archive, never the source file.

## Capabilities (Signing & Capabilities tab)

| Capability | Needed by | Notes |
| --- | --- | --- |
| **Push Notifications** | `@capacitor/push-notifications` | Adds `aps-environment` to the entitlements file. Xcode writes `development` for a local run and `production` for an App Store / TestFlight archive — this is the single most common cause of "the token registers but nothing arrives"; see `APNS_ENV` in TESTFLIGHT.md. |
| **Keychain Sharing** | *not required* | `@aparajita/capacitor-secure-storage` uses the app's own default keychain access group. Only add this if a share extension ever needs the session. |

## Pods

`npx cap sync ios` runs `pod install` and picks up the two plugins added in this
pass (`@capacitor/push-notifications`, `@aparajita/capacitor-secure-storage`)
from `package.json`. If Xcode reports a missing module after a `git pull`, that
is a stale `Pods/` — `npx cap sync ios` again.

## Widget and Shortcut: what they would take

Both are **native Swift targets**. Capacitor cannot produce either: a widget runs
in a separate process that never loads the web view, and an App Intent has to be
compiled Swift for the system to index it. Neither is implemented, and neither
should be faked with a notification.

**Home-screen widget** ("is it airworthy?", tach, next item due):

1. Xcode → File → New → Target → **Widget Extension**, embedded in `App`.
2. An **App Group** (`group.com.mytaillog.app`) on both targets — a widget cannot
   read the app's container otherwise.
3. The web app writes what the widget shows into that group's
   `UserDefaults` on each sync. Roughly 20 lines in `sync.ts` behind a
   `Capacitor.isNativePlatform()` guard, plus a tiny Swift plugin to expose the
   write (`UserDefaults(suiteName:)`), because no Capacitor plugin we ship does
   App Groups.
4. `TimelineProvider` in Swift reading those keys. It must render from the group
   alone — the widget is offline and processless.
5. Refresh comes from the app calling `WidgetCenter.shared.reloadAllTimelines()`
   after a sync (same tiny plugin).

Estimate: a day, most of it the Swift plugin and the App Group entitlement, and
it adds a second place the airworthiness verdict is computed unless step 3
copies the already-computed verdict rather than the inputs. Copy the verdict.

**Siri Shortcut / App Intent** ("Hey Siri, log 4.2 hours on the Cessna"):

1. Xcode → New → Target → **App Intents Extension** (iOS 16+).
2. An `AppIntent` per action, with `@Parameter`s and an `AppShortcutsProvider`
   for the spoken phrases.
3. The intent cannot call into the web view, so it must either open the app with
   a deep link (easy, but then it is not a shortcut, it is a launcher) or write
   into the same App Group for the app to drain on next launch (real, but that
   is a second write queue beside `action_queue`, with its own conflict story).

Estimate: two days for the queue-writing version, and it duplicates the one rule
this codebase is built on — every write goes through `enqueue()`. Worth doing
only when a Swift-side shim can call the existing queue, not before.
